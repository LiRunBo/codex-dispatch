# Delegation policy

The coordinator owns the native plan. Apply this policy at actionable boundaries in that plan. It is a decision aid, not a second planner.

## Decision order
1. Establish intent: discussion, planning, execution, or review. A request for a plan authorizes planning only. A request to implement an agreed plan authorizes bounded implementation.
2. Honor the latest explicit executor choice for its stated scope. "This time" is local to the request; "for this project" applies within that project. Never persist preferences globally without permission. If two explicit choices conflict, resolve by scope and recency; ask only if ambiguity materially affects the work.
3. Identify applicable professional skills independently of executor choice. Existing skills retain their methodology and normal invocation behavior. Use the research or general complex-task guide as appropriate.
4. Assess readiness and feasibility: goal, required inputs, access, tools, permissions, outputs and acceptance criteria. Missing scientific decisions stay with the coordinator. Missing execution prerequisites are blockers, not reasons to claim success.
5. For auto routing, favor Codex for cohesive, substantial executable work with observable outcomes when its environment supports it. Favor the coordinator for discussion, judgment, short edits, or tasks where handoff costs exceed benefit. Either agent may perform reasoning and execution; these are defaults based on user preference, not capability claims.
6. Delegate the largest safe cohesive unit with clear acceptance criteria. Keep implementation, debugging and tests together when feasible. Split at genuine dependencies, different permissions, or decisions that need scientific or user judgment.

## Outcomes
- native: proceed using the coordinator and its normal tools/skills.
- delegate: prepare a bounded manifest and call the executor.
- plan_only: discuss or plan without executing.
- blocked: explain missing prerequisite; ask only for a consequential decision or required authorization.
- independent_review: explicitly requested second opinion; separate outputs and compare after completion.

For an explicit Codex request with incomplete inputs, pass a bounded discovery or planning task if that satisfies the request; otherwise clarify the missing requirement. Never silently swap an explicitly selected executor. For an auto route, native fallback is allowed if it can fulfill the task safely; disclose material changes. If an installed skill depends on unavailable tools, propose a scoped split or ask before changing a user-selected executor or required method.

## Handoff contract
Pass objective, relevant conversation decisions, working directory, input paths, permitted change scope, required skills and dependencies, expected outputs and observable acceptance criteria. Preserve native execution planning. Provide the minimum necessary context; omit secrets and irrelevant conversations. Do not forward the dispatch skill itself. Do not recursively delegate back to the coordinator.

## Communication
No mandatory routing ceremony for small tasks. For a substantial handoff, briefly say what Codex will do and why, then execute if authorized. For multi-stage tasks, expose meaningful milestones in the native plan. Verify actual files, results and tests before reporting success. If the result changes the premise, return to the native plan and reassess before dependent work.
